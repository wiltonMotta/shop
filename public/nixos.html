NixOS 从零到专业：面向 0 基础的系统性高效教程

适用对象：完全没有 Linux/NixOS 基础，但愿意动手练习、希望最终达到较专业水平的学习者。
练习环境：Win11 + VMware Workstation Pro 26H1 v26.0.0.25388281，主机内存 16G。
推荐练习 ISO：nixos-graphical-26.05.5591.fd1462031fde-x86_64-linux.iso 先上手，nixos-minimal-26.05.5591.fd1462031fde-x86_64-linux.iso 再进阶复盘。
核心学习法：先建立“为什么”，再练“怎么做”，最后背“高频固定件”。

0. 你学完后应该达到什么水平

学完本教程，你应该能做到：

  1. 理解 NixOS 的核心思想：为什么它不是“另一个 Linux 发行版”，而是一种声明式、可回滚、可复现的系统管理方法。
  2. 能在 VMware 中稳定安装和练习 NixOS 26.05：知道虚拟机怎么配、怎么联网、怎么分区、怎么装系统、怎么修常见问题。
  3. 能读懂和维护 /etc/nixos/configuration.nix：会添加软件、用户、服务、桌面、网络、SSH、VMware guest tools。
  4. 掌握 Nix 的基本命令和 Nix 语言的最小核心：会用 nix shell、nix run、nix develop、nix build、nixos-rebuild，能看懂列表、属性集、函数、let ... in ...、with、inherit。
  5. 理解 Nix store、derivation、binary cache、profile、generation、rollback：不仅会用，还知道背后的原理。
  6. 能用 Flakes 管理系统配置：理解 flake.nix、flake.lock、inputs、outputs、nixosConfigurations。
  7. 具备专业进阶路径：Home Manager、打包、overlay、override、模块系统、服务管理、垃圾回收、升级、备份、迁移。

1. 学习地图：不要一上来就陷进命令海

NixOS 对 0 基础用户的难点不是命令多，而是它的“世界观”和传统 Linux 很不一样。建议按下面顺序学习：

第 1 层：直觉模型
  NixOS 到底解决什么问题？为什么 /nix/store 很重要？

第 2 层：能跑起来
  在 VMware 中安装 graphical ISO，完成第一次 nixos-rebuild switch。

第 3 层：日常配置
  软件、用户、SSH、桌面、网络、中文输入法、VMware guest tools。

第 4 层：Nix 语言
  属性集、列表、函数、let、with、import、模块选项。

第 5 层：系统工程化
  Flakes、Home Manager、模块拆分、Git 管理配置、回滚和升级。

第 6 层：专业能力
  打包、override、overlay、服务模块、二进制缓存、排错、迁移。

记忆口诀：

先懂店，后懂货，再懂账本。
店 = NixOS 的系统模型；货 = 包和服务；账本 = configuration.nix / flake.nix。

2. 从你给的文章开始：二进制分发、源码分发、Nix 之道

你给的链接是 NixOS-CN 的《二进制分发与源码分发》。这篇文章非常适合作为 NixOS 入门第一课，因为它解释了 Nix 为什么出现。

2.1 传统二进制分发：像“超市买现成菜”

以 Debian/Ubuntu 的 APT 为代表：

软件仓库提前编译好包
        ↓
你的机器下载 .deb
        ↓
包管理器把文件放进 /usr/bin、/usr/lib、/etc 等位置

优点：

  • 安装快。
  • 用户不用本地编译。
  • 生态成熟。

缺点：

  • 软件通常被装进全局目录，版本之间容易互相影响。
  • 想做定制变体比较麻烦。
  • 系统状态经常是“历史操作堆出来的”，时间久了很难复现。

通俗比喻：

APT 像把不同商家做好的菜统一摆进你家厨房。吃起来方便，但冰箱里东西越来越乱，哪道菜依赖哪瓶调料不总是清楚。

2.2 源码分发：像“拿菜谱回家现做”

以 Gentoo 的 Portage 为代表：

下载构建脚本 ebuild
        ↓
拉源码
        ↓
按你的 USE flags、编译参数、本机环境编译
        ↓
安装

优点：

  • 高度定制。
  • 可以按机器特性优化。
  • 每台机器都能编译出适合自己的变体。

缺点：

  • 编译耗时。
  • 对新手不友好。
  • 本机环境差异会带来复杂性。

通俗比喻：

Gentoo 像你自己做饭。想少盐、多辣、换油都可以，但每顿饭都要花时间做。

2.3 Nix 的答案：菜谱、成品、冰箱格子全都带编号

Nix 的核心想法：

用 Nix 语言描述“如何构建一个包”，把所有输入记录下来，然后把输出放到 /nix/store/<hash>-<name> 这样的不可变路径里。

例如：

/nix/store/7wzgkjk6l9ng015wnx7dbzq73v4yr97g-nyancat-1.5.2

这个路径中的哈希值由构建输入决定，输入包括：

  • 包名和版本。
  • 源码 URL 与源码哈希。
  • 依赖。
  • 编译工具。
  • 编译参数。
  • 补丁。
  • 测试和元数据。

所以 Nix 同时获得了二进制分发和源码分发的优点：

如果缓存里已有完全相同输入构建出的结果：下载二进制缓存，快。
如果缓存里没有：按表达式从源码构建，灵活。

记忆口诀：

APT 问：我要装什么？
Gentoo 问：我要怎么编？
Nix 问：这个结果由哪些输入唯一决定？

2.4 NixOS 比 Nix 更进一步

Nix 是包管理器。NixOS 是基于 Nix 的 Linux 发行版。

Nix 管包：

安装 firefox、git、vim、python

NixOS 管整台系统：

用户是谁
服务开不开
内核怎么配
引导器怎么装
SSH 开不开
桌面环境是什么
/etc 里的配置文件如何生成

核心一句话：

NixOS 把“系统状态”从手工操作变成一份可版本管理的配置文件。

3. NixOS 的 10 个核心概念：先背框架，再填细节

3.1 /nix/store：不可变仓库

所有包都放在 /nix/store：

/nix/store/<hash>-firefox-xxx
/nix/store/<hash>-openssl-xxx
/nix/store/<hash>-bash-xxx

每个路径带哈希，因此不同版本、不同构建参数的包可以同时存在。

你要记住：

传统 Linux：很多软件共享 /usr/bin、/usr/lib
Nix/NixOS：每个构建结果有自己的 /nix/store/hash-name

3.2 derivation：构建任务说明书

derivation 可以理解为“构建一个东西的完整说明书”：

  • 源码从哪里来。
  • 用哪些依赖。
  • 怎么编译。
  • 怎么安装到输出目录。

3.3 binary cache：别人已经做好的一模一样成品

Nix 通常先查二进制缓存，例如官方缓存：

https://cache.nixos.org

如果缓存里有，就下载；没有才本地构建。

3.4 profile：用户当前使用的一组包

profile 可以理解为“当前启用的软件清单”。Nix 可以让不同用户有不同 profile。

3.5 generation：系统历史版本

每次 nixos-rebuild switch 成功，都会生成一个新的系统 generation。

好处：

  • 配错了可以回滚。
  • 引导菜单可以选择旧版本启动。
  • 升级失败不等于系统报废。

3.6 rollback：回到旧版本

常见回滚方式：

sudo nixos-rebuild switch --rollback

或者开机时在 boot menu 选择旧 generation。

3.7 declarative configuration：声明式配置

传统方式：

sudo apt install nginx
sudo systemctl enable nginx
sudo vim /etc/nginx/nginx.conf

NixOS 方式：

services.nginx.enable = true;

然后：

sudo nixos-rebuild switch

声明式思维是：

我不描述“我做了哪些步骤”，我描述“系统应该长什么样”。

3.8 module system：配置不是一堆脚本，而是一套选项系统

NixOS 的配置像这样：

services.openssh.enable = true;
networking.hostName = "nixos-vm";
environment.systemPackages = with pkgs; [ git vim htop ];

这些不是随便写的变量，而是 NixOS 模块系统定义好的 options。

查选项的地方：

  • NixOS options search：https://search.nixos.org/options
  • 本机也可用：man configuration.nix、nixos-option

3.9 Flakes：把输入版本锁住

Flakes 用 flake.lock 固定依赖版本，减少“昨天能用，今天不能用”的情况。

注意：官方文档仍把 Flakes 标为 experimental，但社区已经广泛使用。

3.10 Home Manager：用户家目录的声明式配置

NixOS 管系统，Home Manager 管用户环境，例如：

  • shell 配置。
  • git 配置。
  • neovim 配置。
  • 用户级软件。
  • dotfiles。

7. 第二次安装：用 minimal ISO 手动装一遍

这一遍是专业化训练。它会让你真正理解 Linux 安装过程。

7.1 进入 root shell

minimal ISO 启动后通常进入命令行环境。先确认网络：

ping -c 4 cache.nixos.org

如果 NAT 正常，通常 DHCP 会自动获得网络。

7.2 找磁盘名

非常重要：你必须以自己机器上的输出为准。

lsblk

常见磁盘名：

/dev/sda
/dev/vda
/dev/nvme0n1

VMware 中常见是 /dev/sda 或 /dev/nvme0n1。下面示例用 /dev/sda，你要按实际情况替换。

警告：下面分区命令会清空目标磁盘。只在虚拟机练习盘上执行。

7.3 UEFI + GPT + ext4 分区方案

目标分区：

/dev/sda1  512M   EFI System Partition  挂载到 /boot
/dev/sda2  剩余   Linux root             挂载到 /

执行：

sudo -i
parted /dev/sda -- mklabel gpt
parted /dev/sda -- mkpart ESP fat32 1MiB 512MiB
parted /dev/sda -- set 1 esp on
parted /dev/sda -- mkpart primary ext4 512MiB 100%

格式化：

mkfs.fat -F 32 -n boot /dev/sda1
mkfs.ext4 -L nixos /dev/sda2

挂载：

mount /dev/disk/by-label/nixos /mnt
mkdir -p /mnt/boot
mount /dev/disk/by-label/boot /mnt/boot

检查：

lsblk -f

你应该看到类似：

sda1  vfat  boot   mounted on /mnt/boot
sda2  ext4  nixos  mounted on /mnt

7.4 生成 NixOS 配置

nixos-generate-config --root /mnt

生成两个关键文件：

/mnt/etc/nixos/configuration.nix
/mnt/etc/nixos/hardware-configuration.nix

记住：

  • configuration.nix：人主要编辑的系统配置。
  • hardware-configuration.nix：安装器根据硬件生成，通常不要乱改。

7.5 编辑最小可用配置

打开：

nano /mnt/etc/nixos/configuration.nix

建议起步配置如下，按需合并到生成的文件里：

{ config, pkgs, ... }:

{
  imports = [
    ./hardware-configuration.nix
  ];

  boot.loader.systemd-boot.enable = true;
  boot.loader.efi.canTouchEfiVariables = true;

  networking.hostName = "nixos-vm";
  networking.networkmanager.enable = true;

  time.timeZone = "Asia/Shanghai";
  i18n.defaultLocale = "zh_CN.UTF-8";
  console.keyMap = "us";

  users.users.study = {
    isNormalUser = true;
    description = "Study User";
    extraGroups = [ "wheel" "networkmanager" ];
    initialPassword = "123456";
  };

  environment.systemPackages = with pkgs; [
    vim
    nano
    git
    wget
    curl
    htop
    tree
    fastfetch
  ];

  services.openssh.enable = true;

  # VMware guest tools：安装后用于改善 VMware 集成体验。
  virtualisation.vmware.guest.enable = true;

  # 如果启用 X11 图形桌面，可使用 vmware 视频驱动。
  services.xserver.videoDrivers = [ "vmware" ];

  # 初学阶段不要随便改。它表示本机第一次安装时的 NixOS 状态版本。
  system.stateVersion = "26.05";
}

注意：

  • initialPassword = "123456"; 只适合学习虚拟机。真实机器不要明文密码。
  • system.stateVersion 不是当前系统版本号，不要每次升级都随手改。它控制一些有状态数据的兼容默认值。

VMware 的复制、粘贴、拖拽文件等集成功能在 Xorg 下支持更好；NixOS Wiki 提到文件复制、粘贴、拖拽在 Wayland 下不支持，只支持 Xorg。

如果你用 GNOME，登录界面通常可以选择：

GNOME on Xorg

如果你用 KDE Plasma，也可以优先选择 X11 session，而不是 Wayland session。

9. NixOS 日常工作流：最重要的 12 条命令

这些命令建议背下来。

9.1 改配置并应用

sudo nano /etc/nixos/configuration.nix
sudo nixos-rebuild switch

9.2 只测试不永久切换

sudo nixos-rebuild test

适合测试服务、桌面配置。

9.3 构建但不切换

sudo nixos-rebuild build

适合检查配置能不能构建。

9.4 下次启动生效

sudo nixos-rebuild boot

适合内核、驱动等你不想当前 session 立即切换的改动。

9.5 回滚

sudo nixos-rebuild switch --rollback

9.6 查看系统 generation

sudo nix-env --list-generations --profile /nix/var/nix/profiles/system

9.7 搜索包

nix search nixpkgs firefox

9.8 临时进入带某软件的 shell

nix shell nixpkgs#git

退出 shell 后，环境消失，但 store 中可能仍有缓存。

9.9 直接运行软件

nix run nixpkgs#hello

9.10 安装用户级软件到 profile

nix profile install nixpkgs#neovim

不过 NixOS 学习中更推荐把常用系统软件写进：

9.11 垃圾回收

sudo nix-collect-garbage -d

-d 会删除旧 generation。新手执行前建议先确认系统稳定，或者先做 VMware 快照。

9.12 查看日志

journalctl -xe
systemctl status sshd

10. /etc/nixos/configuration.nix 逐行理解

典型结构：

{ config, pkgs, ... }:

{
  imports = [ ./hardware-configuration.nix ];

  networking.hostName = "nixos-vm";
  environment.systemPackages = with pkgs; [ git vim ];

  system.stateVersion = "26.05";
}

10.1 第一行是什么

{ config, pkgs, ... }:

这是一个函数。NixOS 配置本质上是一个 Nix 函数，接收参数：

  • config：已经合并出来的配置。
  • pkgs：Nixpkgs 包集合。
  • ...：允许还有其他参数。

10.2 { ... } 是属性集

{
  networking.hostName = "nixos-vm";
}

可以理解为 key-value 字典。

10.3 imports 是导入其他模块

imports = [ ./hardware-configuration.nix ];

以后你会把大配置拆成：

/etc/nixos/
  configuration.nix
  hardware-configuration.nix
  modules/
    desktop.nix
    packages.nix
    users.nix
    services.nix

10.4 with pkgs; [ ... ] 是包列表简写

environment.systemPackages = with pkgs; [
  git
  vim
  htop
];

等价于：

environment.systemPackages = [
  pkgs.git
  pkgs.vim
  pkgs.htop
];

10.5 system.stateVersion 不要乱改

system.stateVersion = "26.05";

它表示你的系统第一次安装时采用的有状态默认值版本。升级系统时通常不改它。

记忆：

system.stateVersion 不是“我要升级到哪个版本”，而是“我的状态数据按哪个历史默认值保持兼容”。

12. Nix 语言最小核心：能看懂配置就够起步

Nix 语言是纯函数式、惰性求值、动态类型的领域专用语言。听起来很吓人，但你一开始只需要掌握 8 个结构。

12.1 字符串

"hello"
"/home/study"

插值：

let name = "NixOS"; in "hello ${name}"

12.2 数字和布尔

1
3.14
true
false

12.3 列表

[ "git" "vim" "curl" ]

注意：列表元素用空格分隔，不用逗号。

12.4 属性集

{
  name = "study";
  age = 18;
}

取值：

user.name

12.5 let ... in ...

let
  a = 1;
  b = 2;
in
  a + b

意思：先定义局部变量，再返回表达式。

12.6 函数

x: x + 1

调用：

let
  add1 = x: x + 1;
in
  add1 2

结果是 3。

12.7 参数集函数

NixOS 配置开头：

{ config, pkgs, ... }:
{
  environment.systemPackages = with pkgs; [ git ];
}

这就是一个接收属性集的函数。

12.8 inherit

let
  name = "hello";
  version = "1.0";
in
{
  inherit name version;
}

等价于：

{
  name = name;
  version = version;
}

12.9 with

with pkgs; [ git vim curl ]

等价于：

[ pkgs.git pkgs.vim pkgs.curl ]

12.10 import

import ./packages.nix

意思是读取并求值另一个 Nix 文件。

13. NixOS 模块系统：从“配置文件”升级到“配置程序”

你写的：

services.openssh.enable = true;

背后发生的是：

NixOS 模块系统收集所有模块
        ↓
检查 option 类型和默认值
        ↓
合并配置
        ↓
生成 systemd unit、/etc 文件、启动脚本、包闭包
        ↓
构建一个新的系统 generation

13.1 模块拆分示例

目录：

/etc/nixos/
  configuration.nix
  hardware-configuration.nix
  modules/
    packages.nix
    users.nix
    vmware.nix

configuration.nix：

{ config, pkgs, ... }:

{
  imports = [
    ./hardware-configuration.nix
    ./modules/packages.nix
    ./modules/users.nix
    ./modules/vmware.nix
  ];

  networking.hostName = "nixos-vm";
  time.timeZone = "Asia/Shanghai";
  system.stateVersion = "26.05";
}

modules/packages.nix：

{ pkgs, ... }:

{
  environment.systemPackages = with pkgs; [
    git
    vim
    curl
    htop
    tree
  ];
}

modules/users.nix：

{ pkgs, ... }:

{
  users.users.study = {
    isNormalUser = true;
    extraGroups = [ "wheel" "networkmanager" ];
    shell = pkgs.bashInteractive;
  };
}

modules/vmware.nix：

{ ... }:

{
  virtualisation.vmware.guest.enable = true;
  services.xserver.videoDrivers = [ "vmware" ];
}

13.2 为什么拆分

不拆分时：

configuration.nix 越来越长，最后不敢改。

拆分后：

包在 packages.nix
用户在 users.nix
桌面在 desktop.nix
服务在 services.nix
虚拟化在 vmware.nix

这是专业 NixOS 配置管理的第一步。

14. Flakes：让系统配置可复现、可迁移

14.1 Flakes 解决什么问题

传统 channel 方式：

你的 nixpkgs 版本依赖系统 channel 当前指向哪里

Flakes 方式：

flake.nix 声明输入
flake.lock 锁住输入版本

记忆：

flake.nix 是菜单，flake.lock 是采购批次号。

14.2 启用 Flakes

在 configuration.nix 中：

nix.settings.experimental-features = [ "nix-command" "flakes" ];

然后：

sudo nixos-rebuild switch

14.3 最小 flake.nix

建议把配置迁到：

/etc/nixos/flake.nix
/etc/nixos/configuration.nix
/etc/nixos/hardware-configuration.nix

示例：

{
  description = "My NixOS VMware lab";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
  };

  outputs = { self, nixpkgs, ... }:
  {
    nixosConfigurations.nixos-vm = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
      ];
    };
  };
}

使用：

cd /etc/nixos
sudo nixos-rebuild switch --flake .#nixos-vm

14.4 更新 Flake 输入

cd /etc/nixos
sudo nix flake update
sudo nixos-rebuild switch --flake .#nixos-vm

更谨慎的做法：

sudo nix flake update
sudo nixos-rebuild build --flake .#nixos-vm
sudo nixos-rebuild test --flake .#nixos-vm
sudo nixos-rebuild switch --flake .#nixos-vm

14.5 Git 管理配置

cd /etc/nixos
sudo git init
sudo git add .
sudo git commit -m "initial nixos configuration"

如果不想一直用 sudo 管理 /etc/nixos，可以把配置放到家目录，例如：

/home/study/nixos-config

然后：

sudo nixos-rebuild switch --flake /home/study/nixos-config#nixos-vm

16. 开发环境：NixOS 最强的日常能力之一

16.1 临时环境

nix shell nixpkgs#python3 nixpkgs#nodejs

16.2 项目级 devShell

flake.nix：

{
  description = "Example development shell";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";

  outputs = { self, nixpkgs }:
  let
    system = "x86_64-linux";
    pkgs = import nixpkgs { inherit system; };
  in
  {
    devShells.${system}.default = pkgs.mkShell {
      packages = with pkgs; [
        git
        python3
        nodejs
      ];

      shellHook = ''
        echo "Welcome to this dev shell"
      '';
    };
  };
}

进入：

nix develop

退出：

exit

16.3 为什么这很强

传统开发环境：

README 写：请安装 Python 3.11、Node 22、某某库……
每个人装出来都可能不一样。

Nix 开发环境：

flake.nix 写清楚依赖
flake.lock 锁定版本
nix develop 一键进入

17. 打包入门：理解 Nixpkgs 的门槛

最小打包示例：

{ stdenv, fetchurl }:

stdenv.mkDerivation rec {
  pname = "hello";
  version = "2.12";

  src = fetchurl {
    url = "mirror://gnu/hello/hello-${version}.tar.gz";
    hash = "sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=";
  };
}

你现在不必立刻会写复杂包，但要理解：

包 = 一个函数
输入 = 依赖、源码、参数
输出 = /nix/store/hash-name

17.1 override

override 用于改函数参数：

pkgs.foo.override { barSupport = true; }

17.2 overrideAttrs

overrideAttrs 用于改 derivation 属性：

pkgs.foo.overrideAttrs (old: {
  version = "new-version";
})

17.3 overlay

overlay 用于给整个包集合叠一层修改：

(final: prev: {
  myPackage = prev.callPackage ./my-package.nix { };
})

记忆：

override：改一个包的参数
overrideAttrs：改一个包的构建属性
overlay：改整个包集合

18. 服务管理：NixOS 与 systemd

NixOS 大量服务最终都会生成 systemd unit。

常用命令：

systemctl status sshd
sudo systemctl restart sshd
journalctl -u sshd -e
journalctl -xe

18.1 NixOS 开服务的方式

services.openssh.enable = true;

然后：

sudo nixos-rebuild switch

18.2 不推荐新手手动 enable 系统服务

传统 Linux：

sudo systemctl enable nginx
sudo systemctl start nginx

NixOS 中更推荐：

services.nginx.enable = true;

再：

sudo nixos-rebuild switch

因为手动 systemctl enable 可能和声明式配置不一致。

19. 垃圾回收、磁盘空间与 /nix/store

NixOS 会保留旧 generation，方便回滚，但也会占用磁盘。

查看磁盘：

df -h
sudo du -sh /nix/store

删除旧 generation 和未引用 store path：

sudo nix-collect-garbage -d

更温和：

nix-collect-garbage

NixOS 配置自动 GC 示例：

nix.gc = {
  automatic = true;
  dates = "weekly";
  options = "--delete-older-than 14d";
};

注意：

删除旧 generation 后，能回滚的历史会减少。新手建议先做 VMware 快照，再清理。

21. 故障排查：按层次，不要乱试

NixOS 排错建议按这 6 层：

1. 命令写错了吗？
2. Nix 语法错了吗？
3. option 名称错了吗？
4. 包名不存在或变了吗？
5. 服务启动失败了吗？
6. 系统层面，如引导、驱动、网络、磁盘？

21.1 Nix 语法错误

常见错误：

忘记分号 ;
列表里误用逗号
字符串没加引号
花括号不匹配

Nix 中属性赋值要分号：

networking.hostName = "nixos-vm";

列表不用逗号：

[ git vim curl ]

21.2 option 不存在

错误类似：

The option `xxx.yyy.zzz` does not exist

处理：

  1. 去 https://search.nixos.org/options 搜索。
  2. 看报错有没有提示 renamed。
  3. 确认你用的是 NixOS 26.05 对应文档。

21.3 包不存在

nix search nixpkgs 包名

或者打开：

https://search.nixos.org/packages

21.4 服务失败

systemctl status 服务名
journalctl -u 服务名 -e
journalctl -xe

21.5 网络问题

查看 IP：

ip addr

查看默认路由：

ip route

NetworkManager：

nmcli device
nmcli connection show

21.6 VMware 没网

检查：

VMware Network Adapter 是否 NAT
Win11 是否允许 VMware NAT 服务运行
虚拟机内是否启用 networking.networkmanager.enable
是否有 IP 地址

26. 新手最容易误解的 12 件事

26.1 “我装了包，为什么命令没有？”

你可能只是写进配置但没 rebuild。

sudo nixos-rebuild switch

26.2 “我能不能直接 apt install？”

NixOS 不使用 APT。用 Nix/NixOS 的方式管理包。

26.3 “为什么不建议手工改 /etc？”

因为 NixOS 中很多 /etc 文件由配置生成。你手工改可能下次 rebuild 被覆盖。

26.4 “为什么安装同一个包有很多方式？”

因为层次不同：

nix shell：临时
nix profile：用户 profile
configuration.nix：系统级声明式
Home Manager：用户级声明式
flake devShell：项目开发环境

26.5 “system.stateVersion 是不是要跟着升级？”

通常不要。它不是系统版本选择器。

26.6 “Flakes 是不是必须？”

不是必须，但非常适合专业化配置管理。官方仍标为 experimental，社区广泛使用。

26.7 “NixOS 会不会很占磁盘？”

会比一些传统发行版更容易积累历史版本和 store path。学会 GC 即可。

26.8 “为什么配置里有些选项网上教程不一样？”

NixOS options 会演进。以你当前版本的 options search 和构建错误为准。

26.9 “为什么 VMware 复制粘贴不稳定？”

确认：

virtualisation.vmware.guest.enable = true;

并优先用 Xorg session。Wayland 下 VMware 集成功能有限。

26.10 “为什么有时会从源码编译很久？”

可能原因：

缓存中没有对应构建结果
你改了构建参数
用了不常见包或 overlay
网络访问缓存失败

26.11 “为什么包名和命令名不一致？”

Nixpkgs 属性名不一定等于命令名。用：

nix search nixpkgs <keyword>

26.12 “为什么我看不懂别人复杂 flake？”

正常。先掌握最小 flake.nix，再学 let、模块拆分、Home Manager、flake-parts 等工具。

27. 关键原理深挖：为什么 NixOS 可回滚

传统系统升级常常原地覆盖：

/usr/bin/foo 旧版本被新版本覆盖
/etc/foo.conf 被改写
库文件被替换

NixOS 不是这样。它构建一个新的 system closure：

/nix/store/hash1-system-旧
/nix/store/hash2-system-新

切换时改变的是 profile/symlink 指向，而不是把旧文件原地覆盖。

因此：

旧系统还在 → boot menu 能选旧 generation → 可以回滚

记忆：

NixOS 升级像新建一个平行系统，然后把“当前系统”指针切过去。

28. 关键原理深挖：为什么 NixOS 可复现但不是魔法

Nix 通过记录输入来增强可复现性：

源码 hash
依赖版本
构建脚本
编译参数
补丁

但是现实中仍有边界：

  • 上游源码是否稳定可获取。
  • 构建过程是否真的不依赖时间、网络、CPU 特性等隐性输入。
  • 你的配置是否把所有需要的状态都声明了。
  • 数据库、用户数据、浏览器缓存这类运行时状态不自动变成声明式。

专业理解：

NixOS 让“系统配置和软件环境”高度可复现，但不等于自动备份和复现所有个人数据。

29. 推荐最终配置结构

当你学到第 20 天左右，建议目标结构：

~/nixos-config/
  flake.nix
  flake.lock
  hosts/
    nixos-vm/
      configuration.nix
      hardware-configuration.nix
  modules/
    common.nix
    packages.nix
    users.nix
    vmware.nix
    desktop.nix
    ssh.nix
  home/
    study.nix

flake.nix 统一入口：

{
  description = "My NixOS configurations";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
  };

  outputs = { self, nixpkgs, ... }:
  {
    nixosConfigurations.nixos-vm = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./hosts/nixos-vm/configuration.nix
      ];
    };
  };
}

执行：

sudo nixos-rebuild switch --flake ~/nixos-config#nixos-vm

33. 最后给你的学习建议

NixOS 最难的阶段是前 10 天，因为你同时在学：

Linux 基础
Nix 包管理
Nix 语言
NixOS 模块系统
虚拟机安装

不要试图第一天把所有东西弄完。你的最佳路线是：

先 graphical ISO 成功一次
再 minimal ISO 手动一次
再把配置写进 Git
再迁移到 Flakes
再拆模块
再学 Home Manager
最后学打包和 overlay

真正的 NixOS 能力不是记住某个配置片段，而是形成这套思维：

任何系统状态，都尽量问：它能不能被声明？能不能被版本管理？能不能在另一台机器复现？出了错能不能回滚？

当你开始用这四个问题思考，你就已经从“会用 NixOS”进入“理解 NixOS”了。
